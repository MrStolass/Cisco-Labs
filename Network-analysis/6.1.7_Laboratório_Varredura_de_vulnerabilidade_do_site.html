Incompleto Laboratório - Varredura de vulnerabilidade do site

Objetivos

Neste laboratório, você cumprirá os seguintes objetivos:

  • Parte 1: Iniciar Nikto e Executar uma Verificação Básica
  • Parte 2: Usar Nikto para escanear vários servidores da Web
  • Parte 3: Investigar vulnerabilidades de websites
  • Parte 4: Exportar resultados de Nikto para um arquivo

Contexto / Cenário

Nikto é um scanner de vulnerabilidades popular para a web que pode encontrar injeção de SQL, XSS, e outras vulnerabilidades comuns em sites. Ele pode identificar o software instalado usando cabeçalhos e arquivos de página. Nikto suporta protocolos HTTP e HTTPS.

Recursos Necessários

  • Kali VM personalizada para o curso de Ethical Hacker
  • acesso à Internet

Instruções

Parte 1: Inicie Nikto e realize uma verificação básica

Etapa 1: Lançar Nikto em Kali Linux.

  1. Inicie a sessão no sistema Kali com o nome de usuário kali e a senha kali.
  2. Nikto é pré-instalado em Kali Linux. É uma ferramenta de linha de comando que pode ser lançada utilizando a opção Aplicativo -> Análise de vulnerabilidade -> nikto no menu ou diretamente da linha de comando. Para visualizar o arquivo de ajuda, use o comando nikto --help.
┌──(kali㉿Kali)-[~]
└─$ nikto --help
Que opção de comando irá descobrir apenas as vulnerabilidades de injeção de SQL?
Answer Area
-Tuning+9

Etapa 2: Execute uma verificação básica em scanme.nmap.org.

  1. Nmap.org possui um site configurado para testar verificações Nmap. Você usará esse servidor da Web para executar sua primeira verificação de vulnerabilidade. Inicie o Firefox e navegue até o http://scanme.nmap.org. Leia a descrição do servidor e as restrições que são colocadas sobre ele.
Quais são as limitações que o Nmap.org sugere para o uso de seu servidor?
Answer Area
Menos de 100 verificações, no ferramenta de quebra de senha SSH de força bruta
  1. Use Nikto para fazer uma verificação básica no site da scanme.nmap.org.
┌──(kali㉿Kali)-[~]
└─$ nikto -h scanme.nmap.org

Observação: As verificações do Nikto em um servidor da Internet podem levar alguns minutos para serem concluídas. Aguarde até que o prompt CLI seja retornado para continuar para as próximas etapas. Para encerrar uma verificação em execução, digite CTRL-C.

Qual é a correção recomendada para essa vulnerabilidade?
Answer Area
1) Defina o cabeçalho content-type para corresponder ao tipo de recurso atendido.
2) Adicione o cabeçalho X-Content-Type-Options com um valor de "nosniff" para dizer ao navegador para confiar no content-type enviado, em vez de farejar para encontrar o content-type real. Exemplo:
    X-Content-Type-Options: nosniff
  1. O Nikto verifica os serviços Web da porta 80. Para verificar domínios com HTTPS ativado, você deve especificar a flag -ssl para escanear a porta 443:
┌──(kali㉿Kali)-[~]
└─$ nikto -h https://nmap.org -ssl

Web. Nesta parte, você usará Nikto para escanear servidores nas redes virtuais internas para procurar servidores Web vulneráveis. Parte 3: Investigar vulnerabilidades de sites

Nikto fornece algumas informações sobre as vulnerabilidades descobertas durante as varreduras. Algumas vulnerabilidades estão associadas a um número OSVDB (um banco de dados de vulnerabilidade de código aberto mais antigo), Common Weakness Enumeration (CWE), ou uma CVE (Common Vulnerabilities and Exposures). O OSVDB foi descontinuado em 2016. É possível usar a ferramenta de referência CVE para converter o identificador OSVDB para uma entrada CVE para que você possa pesquisar mais sobre a vulnerabilidade.

  1. Revise as informações que Nikto reportou para o servidor web 172.17.0.2. Os CVEs listados na saída são CVE-1999-0678 e CVE-2003-1418. Use os links CVE na saída de Nikto para encontrar mais informações sobre as vulnerabilidades.
Quais vulnerabilidades são descritas pelos dois CVEs listados?
Answer Area
CVE-1999-0678 refere-se à configuração padrão em algumas versões do Apache que define o ServerRoot como /usr/doc. Isso permite que usuários remotos leiam arquivos de documentação para todo o servidor.
CVE-2003-1418 permite que atacantes remotos obtenham informações confidenciais através do cabeçalho ETag ou do limite MIME multipartes.

  1. Use o Banco de Dados Nacional de Vulnerabilidades (https://nvd.nist.gov) para encontrar informações adicionais sobre os CVEs. Na seção Referências a Conselhos, Soluções e Ferramentas, siga os links para encontrar as medidas de correção necessárias para fechar cada vulnerabilidade.
Qual é a solução fornecida para o CVE-2003-1418?
Answer Area
Existe uma correção do código-fonte que soluciona esse problema.

Parte 4: Exportar Resultados do Nikto para um Arquivo

Nikto pode gerar os resultados de uma varredura em vários formatos, incluindo CSV, HTML, SQL, txt e XML. Além disso, Nikto pode ser emparelhado com Metasploit para lançar exploits contra as vulnerabilidades que você descobrir.

  1. Para exportar um resultado de verificação, use o sinalizador -o seguido pelo nome do arquivo. Exporte os resultados de uma verificação para um arquivo de relatório HTML chamado scan_results.htm. O tipo de arquivo de saída é determinado pela extensão do arquivo.
┌──(kali㉿Kali)-[~]
└─$ nikto -h 172.17.0.2 -o scan_results.htm
  1. Localize o arquivo no diretório /home/kali e abra-o em seu navegador para ver o formato do relatório.
  2. Para especificar um formato de saída de arquivo de texto independente da extensão do arquivo, use a flag -Format . Use a opção formato csv para salvar o arquivo em formato .csv para importar em outros aplicativos de análise.
┌──(kali㉿Kali)-[~]
└─$ nikto -h 172.17.0.2 -o scan_results.txt -Format csv
  1. Use o comando cat para exibir o arquivo scan_results.txt salvo.
Como o arquivo salvo difere da saída mostrada na tela?
Answer Area
No arquivo salvo, cada campo é separado por vírgula.
